# REIM M3.5 执行计划 — 原生功能实现与 Java→C++ 转换

> **定位**：M3 与 M4 之间的增补阶段。M3 继续保留为“演示子集 + 工具链”的实测记录（G3 FAIL），本阶段承接其全部 `not_run` / `partial` 项，目标是把原生游戏补到“大部分单机功能可玩”，并由 Java→C++ 转换器产出可运行的原生可执行文件。
>
> **状态**：2026-11-21 计划草案。以下默认值待用户确认（可改）：
> - 功能范围：**核心单机（Tier A）**；
> - 主产物：**`REIMNative.exe`**（无 UE、无 JVM）；同一份游戏逻辑仍产出 `mc_26.3.dll` 供 UE 可选加载，但 UE 画面不作为本阶段门禁；
> - 翻译策略：**用户本机翻译**，生成的 C++ 不提交、不随包分发；对外分发前做法律评审或清洁室替换；
> - 验证：**允许在开发机离线运行 Java 专用服务器作为差分 oracle**，不进入 Runtime、不随包分发；
> - UI 目标：**复刻原版单人菜单流程与界面**（标题画面、世界列表、创建世界、生存/创造物品栏、容器、HUD、暂停/选项/死亡/加载）；文字走语言文件，资产来自用户 jar/资源包；多人/Realms 按钮显示但禁用；
> - 水渲染：按 **M2 遗留缺陷**处理，在本阶段修复 alpha/排序/动画/水下/waterlogging，不留给 M4。
>
> **依据**：`docs/M3_ACCEPTANCE.md` 的实测缺口、`generated/26.3/` 的 26.3 数据普查、`converter/ledger/26.3.json` 与 `conversion-decisions/26.3.md` 的转换现状。

## 0. 一页结论

- M3 没有实现“大部分 Java 功能”。它完成的是：真实存档读取、20 TPS Runtime、Preview/headless 宿主、R0 UE 渲染、场景/差分/打包工具链，以及一个手写的玩法子集（8 生物、137 配方、35 个原生物品行为等）。M3 自己的验收为 **G3 FAIL**。
- 差距的根因有三条：M3 把“完整”定义成 62 条场景闭环而不是功能对齐；翻译门禁被判定 no-go，所有行为靠手写；存档写入、光照、方块实体、通用模型、数据接管等关键包没有开始。
- 现有 `reim-convert` 只做数据提取、类分析、diff/ledger/patch，**没有解析字节码指令，也没有生成过 C++**。所谓“Java→C++ 转换器”需要在 M3.5 从零建立。
- M3.5 的主线是：**选择性全程序翻译**（以服务器/世界/玩法入口为根做依赖闭包）+ **最小 Java 语义支持运行时** + **原生平台/渲染/热路径替换** + **数据接管** + **差分验证**。
- 主产物是 `REIMNative.exe`：单机、无 UE、无 JVM、无 JDK 即可运行；同一份逻辑编译为 `mc_26.3.dll`，UE 仍是可选表现宿主。
- 门禁 G3.5 以 **功能覆盖、菜单/UI 复刻、存档往返、翻译覆盖、差分、可重复构建、无 JVM、性能、用户试玩** 定义，不再用“场景数量”代替功能完整性。
- **UI 是明确范围，不只是 HUD**：标题画面、单人世界列表、创建世界、加载、生存/创造物品栏、容器、暂停、选项、死亡、语言、资源包都属于 Tier A；“复刻原版”指屏幕流程、布局、键位与交互语义对齐，资产使用用户自有 jar/资源包，不复制 Mojang 资产进仓库。
- **水渲染是 M2 欠账**：M2 R0 使用固定 0.72 alpha、按 section 排序且无 OIT、无水面动画/流动/waterlogging；用户已指出该问题。M3.5 在 M35-G1 专项修复，Preview/`REIMNative.exe` 必须通过水上/水下/流动/排序验证。

### 1.3 为什么 M3 没有实现大部分功能

1. **范围定义不同**：`M3_PLAN §1.3` 把“完整游戏”定义为“一组公开场景能稳定完成的单机闭环”，不是 26.3 功能对齐。红石、附魔、酿造、铁砧、村民交易、Boss、末地等被显式后置。
2. **翻译门禁 no-go**：`conversion-decisions/26.3.md §8` 决定 M3 不翻译任何 Java 代码。没有翻译，就只能手写子集；手写无法覆盖 1288 方块 / 161 实体 / 2042 配方。
3. **关键包未开始**：M3-B（存档写入）、C4（光照）、C6（方块实体）、C7（通用模型）、K4（数据接管玩法）、G1（数据驱动世界生成）等在工作包表中存在，但实测记录为未完成；阶段 4/5 的结论也明确写明不完整。

### 1.4 转换器现状

| 能力 | 现状 |
|---|---|
| 数据提取 | 有：blocks/items/recipes/loot/tags/models/biomes/worldgen/assets |
| Java 类分析 | 有：类/方法/字段、字节码 hash、依赖图、反射/Unsafe/JNI 扫描 |

| 可运行 exe 产物 | 无：当前可运行产物是 Preview/headless 与 UE Shipping RC |

### 1.5 M2 遗留缺陷：水渲染

用户实测指出水渲染有问题。这是 **M2 R0 的已知限制**，不是 M3.5 新引入；M3 的 J2 只做了 3×3 群系 tint，水动画/水下/排序仍未完成。证据：

- `docs/M2_ACCEPTANCE.md` §6：水体 alpha 0.72 兜底、按 section 排序、无 OIT。
- `docs/M2_ACCEPTANCE.md` §17.4：动画纹理/水面动画“M2 内不解决”。
- `docs/M3_ACCEPTANCE.md` §3.9：J2 仅 3×3 biome tint；水动画、平滑光照、AO 未做。
- `runtime/preview/gl_renderer.cpp`：透明 pass 对水再乘 0.72；透明 section 只按包围盒中心排序。
- `runtime/mc-native/mesh/section_mesh.cpp`：水按整方块几何发射，没有流动高度/waterlogging/角高。

| 问题 | 现状 | 影响 | M3.5 目标 |
|---|---|---|---|
| 透明度 | 固定 `alpha *= 0.72`，不读原版水体 alpha/资源包 | 水色/透明度不随群系/资源包 | 按资源包/原版 water 渲染类型取 alpha |
| 排序 | 只按 section 中心排序，无逐面排序/OIT | 水+玻璃+树叶/多层水闪烁、遮挡错误 | 逐面排序或 OIT；独立 water pass |
| 水面动画/流动 | 静态图集，无帧动画/流动方向 | 水看起来是静止的 | `water_still`/`water_flow` 帧动画 + 流向 |
| 流体高度/waterlogging | 整方块水面；无流动高度/角高/waterlogged | 台阶/楼梯/栅栏/半砖水错误 | 流体高度、waterlogged 数据与网格 |
| 水下/双面 | 背面剔除+水下雾；无水面背面/overlay | 水下看水面消失/错误 | 水下双面、正确 cull、水下雾/overlay |
| 群系水色 | 3×3 tint 近似 | 边界色带/资源包色差 | 原版平滑混合/资源包 color |
| UE/Preview 一致性 | UE R0 同样 0.72 + section 排序 | 两 Host 视觉不一致 | 同一 Runtime 数据 + 一致性测试 |

M3.5 在 **M35-G1** 专项修复；UE 可选，但 Preview/`REIMNative.exe` 必须通过水上/水下/流动/排序验收。

## 2. 范围

### 2.1 范围档位

| 档位 | 内容 | 定位 |

| **Tier A — 核心单机（本阶段默认）** | 生存/创造/硬核；全部内容数据；主世界/下界/末地；主要结构；≥80% 实体；存档/光照/方块实体；复刻原版菜单/创建世界/物品栏；基础命令子集；水渲染修复；完整音频/R1-R2 渲染 | M3.5 门禁 |

- 启动 Java Edition、运行 JVM/classpath、在 Runtime 内解释字节码或动态加载类。
- 通用 Java→C++ 编译器产品；只做 Minecraft 26.3 的选择性、可验证翻译。
- 多人/协议/服务器互通、Java Mod/Mixin/Forge/Fabric、OptiFine/Iris。
- 26.3 全量位级一致；完整 DFU 旧存档迁移。
- M4 的 Launcher UI、安装器、账号、更新通道。
- 把翻译产物作为对外分发包直接发布（需要单独法律评审）。
- 把多人/Realms 做成可用入口；只显示禁用状态，不伪造可用。
- 逐像素复刻原版 UI 或把 Mojang 资产提交进仓库；“复刻”指流程/布局/交互/语言键对齐，资产来自用户自有 jar/资源包。

### 2.4 “复刻原版”UI 明确清单

“复刻原版” = 屏幕流程、布局、键位、交互语义、语言键与资产引用对齐；不要求逐像素一致，不复制 Mojang 资产进仓库。资产来自用户自有 jar/资源包；缺失时明确回退。

| 屏幕 | Tier A 必须 |
|---|---|
| 标题画面 | 背景/logo/splash 来自用户资源；Singleplayer 可点；Multiplayer/Realms 显示但禁用并提示；Options；Quit；Language |
| 单人世界列表 | 世界条目（名称/模式/版本/最后游玩/图标可选）；进入、创建、编辑、删除、重建；空列表提示 |
| 创建世界 | 名称、种子、游戏模式（生存/创造/硬核）、难度、允许作弊、世界类型（默认/超平坦）、生成结构、奖励箱；校验与默认值 |
| 加载 | 世界生成/加载进度、状态文字；失败可返回 |
| HUD | 快捷栏、生命/饥饿/护甲/氧气/经验、准星、手持物名、状态图标；GUI 缩放 |
| 生存物品栏 | 2×2 合成、护甲/副手、玩家预览、提示/拖拽/Shift 点击/丢弃 |
| 创造物品栏 | 标签页/搜索/物品面板/快捷栏；无限物品；拖拽/删除 |

## 3. 产物形态

### 3.1 `REIMNative.exe`（主产物）

```text
build/native/26.3/
  REIMNative.exe              # 原生宿主 + 游戏逻辑 + 渲染/UI/音频
  mc_26.3.dll                 # 同一份游戏逻辑，供 UE 可选加载
  data/                       # manifest、覆盖报告、翻译报告
  generated/26.3/             # 用户本机由 jar 生成的数据/资产（不入库）
  logs/
```

`REIMNative.exe` 包含：

- 原生运行时：世界状态、区块/区段、物理/碰撞、存档、光照、方块实体、模拟线程；
- 转换器生成的 C++：Java 字节码翻译结果 + 最小 Java 语义支持运行时（NJS）；
- 原生表现层：窗口/输入/音频/渲染/UI（由现有 Preview 渲染器升级而来，走同一 Contract）；
- 用户本机生成的 26.3 数据与资产。

运行前置：Windows x64 + VC++ 运行库；**不需要 UE、JDK、JVM、MSVC、CMake、Visual Studio**。数据/资产由用户在 Developer Mode 用自有 jar 生成；官方分发形态由 M4 决定。

### 3.2 可选 `mc_26.3.dll` / UE

- 同一份游戏逻辑编译为 `mc_26.3.dll`，UE Host 可按现有 Contract 加载。
- UE R0 不得回归；R1/R2/UI/音频由 UE 侧后续接入，不作为 M3.5 的门禁。
- Preview/headless 继续作为回归/差分 Host；`REIMNative.exe` 是玩家面向的功能验收 Host。

### 3.3 分发与法律边界

- 翻译生成的 C++ 属于用户自有 Java 输入的衍生结果。**生成物不提交仓库、不随产品分发**；仓库只保留生成器、映射、补丁、覆盖报告与哈希。
- 官方对外分发（M4 及以后）前必须做法律评审；可选路径：
  1. 清洁室替换翻译模块（按 port ledger 逐步原生化）；
  2. 仅在本机 Developer Mode 生成 exe，不分发；
  3. 获得明确授权后分发。
- 不随包分发 Mojang 的 jar、纹理、声音、模型或“实质性部分”。

### 3.4 为什么不以 UE Shipping 作为本阶段主产物

- UE 5.8.4 的 Cook/打包/Zen 依赖重，当前 Host 只接 R0；功能迭代会被 UE 集成拖慢。
- 本阶段要验证的是“Java 功能是否被正确翻译成 C++ 并在原生游戏里可玩”，独立 exe 的反馈回路最短。
- UE 仍是可选的最终表现宿主；M4 再决定最终分发形态。

## 4. 转换器架构

### 4.1 流水线

```text
prepare → data → analyze → translate → build → verify
```

- `prepare/data/analyze`：沿用 M1–M3 的摄取、数据生成、类分析。
- `translate`（新增）：字节码 → IR → C++ + 支持运行时绑定 + 原生替换表 + 覆盖报告。
- `build`（新增/扩展现有 NativeBuild）：CMake/MSVC 编译 `REIMNative.exe` 与 `mc_26.3.dll`。
- `verify`：manifest/哈希/无 JVM/可重复性/覆盖报告校验。

所有命令固定输入、固定排序、无时间戳；同输入两次输出一致。

### 4.2 前端、IR 与 C++ 生成

1. **Classfile 前端**：扩展现有 `converter/java-analyzer` 的自研解析器，完整读取常量池、方法 `Code`、异常表、局部变量表、BootstrapMethods、`invokedynamic`。如引入 ASM，按 `third_party` 许可证审计并记录版本。
2. **指令解码**：JVM 指令 → 带类型的栈式 IR；处理分支、switch、异常表、monitor、数组、字段/方法引用。
3. **类层次与分派**：构建超类/接口图，生成 vtable/itable；静态/虚/接口/特殊调用映射到 C++。
4. **C++ 生成**：每个 Java 方法生成一个 C++ 函数，使用显式操作数栈、局部变量、异常分支；类/字段/静态初始化映射为 C++ 类型与函数。第一阶段以**正确性优先**，不追求可读性。
5. **依赖闭包**：以服务器 tick、世界生成、方块/物品行为、实体、容器、配方/战利品为入口，翻译可达类；客户端渲染/平台类走原生替换或拒绝；生成逐类覆盖报告。
6. **确定性**：固定类/方法遍历顺序、稳定命名、无时间戳；两次 `translate` 字节一致。

### 4.3 支持运行时（NJS，不是 JVM）

翻译后的代码需要一个最小的 Java 语义运行时：

- 对象模型、虚表/接口、数组、UTF-16 字符串、装箱类型；
- 异常、`finally`、类初始化、最小栈回溯；
- 常用集合（ArrayList/HashMap/HashSet/EnumMap 等）、`java.util.Random`/`SplittableRandom`、`Math`/`StrictMath` 包装；
- lambda/`invokedynamic` 适配；`Optional`；按需的 Stream 子集（无法支持时在翻译期明确报错，不静默改变语义）；
- NBT、DataFixerUpper/Codec、JSON/Gson 兼容层（按实际闭包裁剪）；
- 堆与 GC：翻译对象图需要可回收；采用简单的 stop-the-world mark-sweep 或等价的确定性内存管理，禁止无限泄漏；
- 原生适配：文件、线程、时间、网络（本阶段不实现多人，网络类拒绝/桩化）；
- 反射/Unsafe/ClassLoader：静态分析面很小；翻译期遇到即明确失败或替换为原生适配，**不做运行期类加载**。

### 4.4 翻译边界

| 类别 | 策略 |
|---|---|
| 服务器/世界/玩法 | 优先翻译：`net/minecraft/world/**`、`server/**`、`core/**`、`util/**`（按闭包）、`nbt/**`、配方/战利品/世界生成相关类 |
| 客户端渲染/平台 | 原生：`net/minecraft/client/**`、`com/mojang/blaze3d/**`、`renderpearl/**`、realms、LWJGL/OpenGL |
| 网络/多人 | 本阶段不实现；协议/连接类桩化或拒绝 |
| 反射/Unsafe/ClassLoader | 翻译期失败并报告；必要时原生替换 |
| 热路径 | 原生覆盖：碰撞/物理、区块网格、噪声、存档 I/O、渲染、UI、音频 |
| 无法翻译 | 记录到覆盖报告，回退原生实现或降级；不伪造“已翻译” |

边界写入 `translation-boundary.json`，每个类/方法标注 `translated / native / stub / failed`。

### 4.5 生成代码与 Patch

- 生成代码不手改；修正进入版本化 Patch 集或原生替换表。
- Patch 目标可以指向生成文件/符号，但必须可重放、可三路合并、冲突显式失败。
- 每个子系统有 port ledger 条目：Java 符号 ↔ 生成模块/原生模块/Patch/证据。
- 不散落 `#if MC_VERSION`；版本差异集中在 profile/数据/Patch。

### 4.6 性能策略

- 第一版 C++ 生成以栈式语义正确为先，性能可能明显低于 Java。
- 逐子系统 profile：tick 热点、世界生成、AI、碰撞、网格、存档。
- 对热点使用原生覆盖（碰撞/物理、噪声、网格、I/O、渲染）或 IR 优化（局部变量提升、去栈、内联、常量折叠）。
- 性能门禁：20 TPS ±0.2；生成/存档不阻塞 tick；exe 渲染 FPS 达到用户可玩阈值（本阶段先定 60 FPS @ 1080p 的目标，按机器记录）。

### 4.7 覆盖报告

`translate_report.json` / `coverage_report.json` 至少包含：

- 类/方法总数、翻译/原生/桩/失败数量与百分比；
- 每个子系统的入口、闭包、未支持原因；
- 生成代码哈希、支持运行时版本、原生替换表哈希；
- 与 `generated/26.3` 数据版本的绑定；
- 两次运行一致性。

**依赖**：S1 是硬前置；S2 与 S3 可部分并行（E1/E2 先于 F2）；S4 依赖 S2/S3；S5 依赖 S4。S1 的纵切选择应优先覆盖“对象/集合/异常/接口”等支持运行时语义，避免后期才发现 JRT 缺口。

## 8. 验证与差分

### 8.1 oracle

- 首选：开发机离线运行 26.3 **专用服务器**（固定种子/时间/输入），导出区块、tick、配方、战利品、实体、光照等基准；oracle 产物不进入 Runtime、不随包分发。
- 不启动游戏客户端；不构造 Java 启动路径；oracle 与 Runtime 完全隔离。
- 若用户不批准任何 Java 进程，降级为静态 fixtures/数据报告，并在 G3.5 记录差分覆盖不足（不写成通过）。

### 8.2 差分

- 每个翻译子系统有固定输入/固定种子/固定 tick 的对照样本；
- 比较语义 dump 而非位级二进制；差异必须可解释；
- 阈值在 S1 用 oracle 校准并冻结，后续不得为了让测试通过而放宽。

### 8.3 存档往返

Native 读 → 写 → 原版读；原版写 → Native 读 → 写 → 原版读；覆盖未知字段、压缩变体、LZ4、`.mcc`、玩家/实体/POI、拆分数据文件。

### 8.4 场景

- 场景是功能合同，不是门禁数字游戏；每个 Tier A 系统至少一条可判定场景；
- 场景在 headless/`REIMNative.exe` 可判定，不依赖 UE；
- 未实现功能写 `not_run`，不得用空场景/跳过场景计为通过。

### 8.5 无 JVM 审计

- 源码扫描 Runtime/生成代码/exe 导入；0 个 `jvm.dll`/`java.exe`/`javaw.exe`/classpath/字节码解释器命中；
- 支持运行时是静态 C++，不做运行期类加载；
- 生成代码中若出现反射/Unsafe/ClassLoader，必须翻译期失败并记录。

### 8.6 可重复性

- `translate` 与 `build` 同输入两次一致；类/方法排序、命名、哈希稳定；
- 不承诺跨机器字节一致；使用 canonical hash 并记录工具链版本；
- 失败保留中间产物与日志。

### 8.7 性能

- 模拟：20 TPS ±0.2；tick p99 预算；生成/存档不阻塞；
- 渲染：exe 在目标机器上的 FPS/帧时间基线；
- 内存：30 分钟 soak 无持续增长；翻译对象堆有 GC/回收验证；
- 记录机器/场景/阈值，不把开发机样本写成通用承诺。

### 8.8 菜单/UI 复刻验证

- 屏幕流程断言：启动→标题→世界列表→创建世界→加载→HUD→物品栏→容器→暂停→保存退出→再进入；
- 布局/命中：不同 GUI scale/分辨率下槽位/按钮命中一致；HUD/生存物品栏/创造物品栏标签页；
- 键位：E/Esc/1–9/Q/Shift/Ctrl/Space/鼠标左右键；改键生效；
- 文本：语言键来自 `lang`；en_us/zh_cn；缺失回退；
- 资产：logo/splash/panorama/字体/声音来自用户 jar；缺失回退；
- 禁用项：多人/Realms/Open to LAN 显示禁用，不伪造；
- 截图基线：标题/世界列表/创建世界/生存物品栏/创造物品栏/容器/暂停/选项/死亡。

### 8.9 水渲染验证

- 固定相机：水上俯视/平视、水下、流动水、waterlogged 台阶/楼梯/栅栏；
- 排序：水+玻璃+树叶/多层水；无闪烁/错误遮挡；
- 颜色：群系水色/资源包覆盖/雨天/夜晚；
- 动画：`water_still`/`water_flow` 帧序列固定 tick；流向；
- 一致性：Preview/`REIMNative.exe`（UE 可选）同场景截图差异阈值；
- 失败项写 `not_run`，不用静态蓝色水面冒充通过。

## 9. 风险

| 风险 | 级别 | 影响 | 缓解 |
|---|---|---|---|
| 翻译闭包过大（world+server+util 数千类） | **极高** | 无法在可接受时间内完成 | 入口/闭包裁剪；原生替换；Tier A 范围；逐子系统门禁 |
| Java 语义缺口（集合/异常/lambda/Stream/浮点） | **高** | 行为偏差/难定位 | NJS 对照测试；不支持项翻译期失败；差分 oracle |
| 生成代码性能不足 | **高** | 20 TPS/FPS 不达标 | 栈式正确性优先；热点原生覆盖；IR 优化；profile |
| 渲染器工作量（独立 exe 的 R1/R2） | **高** | 画面不可用/拖慢功能 | 升级现有 Preview 渲染器；分档（先可玩后保真）；UE 可选 |
| 存档兼容复杂（Anvil/玩家/实体/POI/压缩） | **高** | 数据损坏/原版不可读 | E2 专项；往返矩阵；原子写；不降级 |
| 法律/衍生作品/分发 | **极高** | 无法发布 | 生成物不提交；本机 Developer Mode；分发前评审；可清洁室替换 |
| oracle 不被批准 | 中 | 差分覆盖不足 | 静态 fixtures；降低门禁口径；显式记录 |
| 范围蔓延（红石/附魔/村民/Boss） | **高** | 阶段无法收口 | Tier A 冻结；Tier B/C 后置；变更写 Scope Changes |
| 世界生成/结构/维度广度 | **高** | “大部分功能”仍缺 | 先数据驱动 + 主结构；末地/结构分波；不承诺全量 |
| 复刻原版 UI/菜单范围 | **高** | 标题/创建世界/物品栏/选项做不完 | §2.4 明确清单；先流程/布局/交互，再做保真；截图/断言 |
| 水渲染（M2 欠账） | **高** | 水下/流动/排序仍错误 | M35-G1 专项；独立 water pass；固定相机回归；不静态凑数 |
| 创造模式/物品面板 | 中高 | 创造物品栏/飞行/无限物品缺失 | 创造模式纳入 Tier A；物品面板按 §2.4；Tier B 扩展 |
| CJK 字体/语言 | 中 | 中文 UI 缺字/回退 | 用户 jar 字体；zh_cn 语言键；缺失回退 en_us |
| 版本升级 | 中 | 26.3 之后维护成本 | diff/translate/patch 机制；真实第二版本再演练 |

## 10. 前置与用户决定

1. **范围确认**：Tier A 是否作为 G3.5 合同；Tier B/C 是否后置；UI 是否按 §2.4 全量清单（含创造/硬核、基础命令、zh_cn）。
2. **产物确认**：`REIMNative.exe` 是否为主验收产物；UE Shipping 是否仅保持 R0 不回归。
3. **翻译/分发**：是否接受“本机翻译、生成物不提交/不随包分发”；官方分发前法律评审。
4. **oracle**：是否允许开发机离线运行 26.3 专用服务器作为差分基准；若不允许，按 §8.1 降级。
5. **M3/M2 欠账**：M3 记 G3 FAIL，B1/B2/B3/B4/B5、C4、C6、C7、K4、G1 等直接并入 M3.5；**M2 水渲染缺陷（§1.5）** 也在 M3.5 修复（默认）。
6. **UI 复刻深度**：先做流程/布局/交互/键位/语言键对齐，还是要求逐像素；默认前者，逐像素作为后续保真项。
7. **环境**：磁盘/内存/GPU；26.3 client/server jar 与真实存档路径；第二版本输入（本阶段不强制）。
8. **试玩**：每个执行阶段结束需要用户实际试玩并给出问题清单，不以自动化替代。

## 11. 完成定义

M3.5 完成必须同时满足：

- `REIMNative.exe` 可在未安装 UE/JDK/MSVC/CMake/Visual Studio 的 Windows x64 机器上启动，走完标题画面→创建/选择世界→加载→游玩→物品栏/容器→暂停→保存退出→再进入；
- Tier A 功能矩阵逐项达标，核心内容无 `data_only`，未支持项显式列出；
- 真实存档读写往返通过，原版可读取 Native 写出的存档；
- 世界生成/光照/方块实体/实体/容器/UI/音频/渲染达到 §2.2；
- 标题画面、世界列表、创建世界、生存/创造物品栏、容器、HUD、暂停、选项、死亡、语言（en_us/zh_cn）按 §2.4 可用；
- 生存/创造/硬核可用；基础命令子集可用；多人/Realms/Open to LAN 明确禁用；
- 水渲染通过 §8.9：水上/水下/流动/waterlogging/排序/群系水色；不再是固定 0.72 alpha + section 排序；
- 转换器可重复产出 C++、支持运行时、覆盖报告与 port ledger；
- 无 JVM/无运行期类加载/无字节码解释器；
- 差分/存档/性能报告齐全，`not_run` 与豁免显式；
- 用户试玩确认核心闭环可完成；
- 生成物不提交、不随包分发；分发决策留给 M4 与法律评审。

## 12. 与 M3 / M4 的关系

- **M2**：水渲染的 0.72 alpha/section 排序/无动画属于 M2 R0 已知限制（`docs/M2_ACCEPTANCE.md` §6、§17.4），M3.5 在 M35-G1 修复；UE R0 不得回归。

- **M4**：Launcher UI 与产品化仍在 M3.5 之后；M4 的前置从“M3 的主要单机能力”改为“M3.5 的可运行原生游戏 + G3.5 通过或豁免”。M4 决定最终分发形态（独立 exe / UE Shipping / 两者）。
- **Converter**：M1–M3 的数据/分析/diff/patch 继续复用；M3.5 新增的翻译层是 Minecraft 专用，不扩张为通用 Java→C++ 编译器。
