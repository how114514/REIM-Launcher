# Conversion decisions — Minecraft Java Edition 26.3

> Audit record for M2 (ROADMAP §5, M2-E8). Decisions describe what the
> Converter and Runtime actually do; they do not claim Java rendering
> translation or full conversion coverage.

## 1. Data generation route

- Block states, models, face sprites/tints and block textures are derived from
  the user's own 26.3 `client.jar` assets by `reim-convert extract`.
- The vanilla data generator reports directory is not started (this
  environment does not start Minecraft/Java); the gap is recorded in
  `generated/26.3/extraction_report.json`.
- `extract` emits schema v2: `manifest.json` (format 2, ABI 2, input and
  generated hashes, atlas descriptor, capabilities), `blocks.json` (stable
  sort, material class, face-level sprite/tint), `textures.json` (atlas tile
  metadata, nearest/no-mip sampling) and `debug_inputs.json` (absolute input
  paths, local diagnostics only; excluded from the manifest and never packed).
- Generated files are never hand-edited. The Runtime and UE Host reject a
  manifest whose schema, profile, ABI or file hashes do not match.

## 2. UE rendering is a Native Adapter

- The UE runtime (`runtime/host`) is a **pinned native adapter**, not a
  translation of Java's render pipeline. There is no Java→UE shader/material/
  RenderType conversion, no command replay and no second world implementation.
- Converter responsibilities are pin, combine, validate and package:
  `converter/adapters/ue/adapter_pin.json` pins adapter identity/version,
  UE 5.8.4, ABI 2 and R0; `generate_ue_adapter.py` records the hashes of the
  adapter's uproject/Config/Content/plugin assets into `ue_adapter.json`.
- The Bridge compiles the same pin (`ReimAdapterPin.h`); a mismatch between the
  descriptor, the pin and the running UE version is a startup failure.

## 3. Contract and version binding

- Rendering Contract v2 (`runtime/contract/reim_abi.h`, `reim_render.h`) is
  frozen for M2: host-owned frame blobs, interpolation snapshots, `get_asset`,
  `get_runtime_info`, render level 0.
- `reim-convert package` binds the exact `mc_26.3.dll` hash, the generated
  manifest hash and the adapter descriptor hash into `native_version.json`
  plus a deterministic `verification.json`.
- `reim-convert assemble` combines the UE Runtime package and NativeVersion
  into a NativeBuild and records all three directory digests in
  `native_build.json`.
- The UE Host loads only `<native_version_path>/mc_26.3.dll`; `dll_path` is
  ignored. At startup it verifies the DLL hash, manifest hash, adapter file
  hash, adapter identity and UE version, and after `create` it checks that the
  Runtime accepted the same manifest hash. Manual assembly does not pass
  (M2-E9).

## 4. R0 rendering scope

- R0 renders chunk geometry supplied by the C++ mesher, an atlas texture from
  `get_asset`, baked vertex light/tint with a directional-light fallback,
  distance fog, sky colour, a debug player proxy and a Runtime-driven camera.
- The S1 implementation uses the plan-permitted degradation:
  `FLocalVertexFactory` with baked vertex colour instead of a custom vertex
  factory. R1 restores the custom VF. This is not a Java shader translation.
- Entities, block entities, particles, weather, audio, post-processing, OIT
  and the full Minecraft UI are out of scope for M2.

## 5. Unsupported / not done

- No JRT expansion, bytecode translation or full DFU adaptation in M2.
- Non-full-cube block models are not meshed (M1 known limitation).
- Single dimension, read-only world, no save writes.
- DX12 is the acceptance path (SM5 observed in S1); DX11 is a smoke item.
- M2 packages are internal acceptance artifacts only; Mojang assets are never
  redistributed.

## 6. S4 visual-correctness extensions (2026-11-21)

- `blocks.json` (format 2, backwards-compatible optional keys) gains:
  `tint_kinds` (per face: `grass`/`foliage`/`water`), `variants` (canonical
  state key such as `snowy=true` or `layers=2` with its own sprite/tint/geometry
  override) and `geometry` (explicit quads for non-cube models: snow layers,
  crosses, ≤2-element boxes). Existing fields keep their meaning.
- `biome_tints.json` (new generated file, listed in `manifest.json`
  `generated[]`) maps each biome to grass/foliage/water colours computed from
  the user's `client.jar` biome JSON and `textures/colormap/{grass,foliage}.png`.
  The Runtime tints grass/foliage/water vertices per block position; missing
  tables fall back to fixed vanilla defaults.
- Model coverage is deliberately bounded: only models with at most two elements
  and no non-cross rotation become geometry. Stairs, fences, doors, walls and
  other multi-element/rotated models remain `skip` until R1; they are not
  approximated.
- These are data/renderer extensions. The ABI v2 vertex layout, frame
  ownership, coordinates and NativeVersion/NativeBuild schemas are unchanged.
